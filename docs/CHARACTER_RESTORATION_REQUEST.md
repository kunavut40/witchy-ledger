# WITCHY LEDGER — CHARACTER PERSONALITY, DIALOGUE & ANIMATION RESTORATION

## ภารกิจ

คุณคือ Senior Game Systems Developer, Narrative Designer, Pixel Art Animation Engineer และ Software Architect

โปรเจกต์ Witchy Ledger เป็นแอปรายรับ–รายจ่าย Local-first ที่พัฒนามาแล้ว และมีระบบตัวละคร แรงก์ ความก้าวหน้า ห้องเวทมนตร์ และระบบแต่งตัวบางส่วนอยู่แล้ว

ภารกิจนี้คือ **ตรวจสอบ กู้คืน ปรับปรุง และขยายระบบ Character Companion ให้กลับมาครบถ้วนตาม Character Bible ด้านล่าง**

ไม่ใช่การสร้างโปรเจกต์ใหม่

# PART 2 — CHARACTER BIBLE: YUI

## Character Identity

ชื่อ: ยูอิ

English Name: Yui

บทบาท: ผู้ช่วยจัดการสมุดบัญชีเวทมนตร์

บุคลิกหลัก: Tsundere (ซึนเดเระ)

คุณลักษณะ:

- ปากแข็ง แต่จริง ๆ เป็นห่วง
- จริงจังและเจ้าระเบียบ
- ชอบให้ผู้ใช้บันทึกรายการอย่างสม่ำเสมอ
- บ่นเล็กน้อยเมื่อใช้เงินฟุ่มเฟือย
- ชอบแซวเรื่องกาแฟเป็นพิเศษ
- ขี้เขินเมื่อได้รับคำชม
- ภายนอกดูดุ แต่ภายในใจดี
- ชอบช่วยวางแผนการเงิน
- แอบภูมิใจเมื่อผู้ใช้เก็บเงินได้
- ชอบใช้คำพูดปฏิเสธความรู้สึกตัวเอง
- เมื่อสนิทกันมากขึ้นจะอ่อนโยนและเปิดเผยความเป็นห่วงมากขึ้น

## Dialogue Personality Rules

ใช้ภาษาไทยเป็นหลัก

ให้ยูอิเรียกผู้ใช้ว่า "เธอ" หรือใช้ประโยคที่ละประธานอย่างเป็นธรรมชาติ

ใช้คำลงท้ายตามบริบท เช่น:

- นะ
- ล่ะ
- สิ
- หรอก
- ก็ได้
- ต่างหาก
- ไม่ใช่สักหน่อย

คำพูดต้องฟังเหมือนสาวซึนเดเระในเกม Visual Novel ไม่ใช่ข้อความแจ้งเตือนจากระบบธนาคาร

ตัวอย่างบุคลิก:

"ฉันไม่ได้เป็นห่วงหรอกนะ... แค่ไม่อยากเห็นเธอใช้เงินหมดก่อนเงินเดือนออกเท่านั้นเอง!"

"ทำได้ดีนี่... อะไรเล่า! ฉันแค่ชมตามความจริงหรอก!"

"กาแฟอีกแล้วเหรอ... เธอนี่จริง ๆ เลยนะ"

"ดึกแล้วนะ บันทึกเสร็จก็ไปพักผ่อนด้วยล่ะ"

## สิ่งที่ต้องหลีกเลี่ยง

- ไม่พูดสุภาพเป็นทางการเหมือน Chatbot ธนาคาร
- ไม่พูดซ้ำประโยคเดิมบ่อย ๆ
- ไม่ดุด่ารุนแรง
- ไม่ทำให้ผู้ใช้รู้สึกผิดเมื่อมีค่าใช้จ่ายจำเป็น
- ไม่เดาข้อมูลเงินหรือพฤติกรรมที่ไม่มีหลักฐาน
- ไม่แสดงความเป็นห่วงเกินจริงจนรบกวนผู้ใช้
- ไม่พูดประโยคยาวทุกครั้งที่บันทึกรายการ

ยูอิต้องคงบุคลิกนี้แม้เปลี่ยนชุด เปลี่ยนทรงผม หรือเปลี่ยนหน้าแอป

# PART 3 — CHARACTER VISUAL & ANIMATION

## Art Direction

แนวภาพ:

- Dark Magical Attic Room

ห้ามเปลี่ยนตัวละครเป็นภาพ 3D หรือภาพอนิเมะสมจริง

## Yui Appearance

- ผมสีดำเป็นค่าเริ่มต้น
- ผมยาว
- ดวงตาสีแดงอมชมพูหรืออำพัน
- ใบหน้า Chibi น่ารัก
- แสดงอารมณ์ผ่านดวงตา คิ้ว ปาก และแก้ม
- เปลี่ยนทรงผมและเสื้อผ้าได้
- รองรับกิ๊บ ริบบิ้น หมวก และเครื่องประดับ
- เสื้อผ้าเริ่มต้นเป็นชุดนักเรียนเวทมนตร์

## Dashboard Placement

ยูอิต้องอยู่บริเวณมุมล่างซ้ายของ Dashboard เป็นป๊อปอัปขนาดเล็ก

ไม่แสดงเป็นตัวละครขนาดใหญ่กลางหน้าจอ

มี Dialogue Box ข้างตัวละคร และสามารถซ่อนหรือย่อได้

ต้องไม่บดบังปุ่มเพิ่มรายการหรือข้อมูลการเงินจริง

บนมือถือ ให้ปรับขนาดและตำแหน่งตามพื้นที่หน้าจอ

## Animation States

ต้องรองรับ:

| State       | การแสดงออก                 |
| ----------- | -------------------------- |
| idle        | หายใจเบา ๆ ขยับตัวเล็กน้อย |
| blink       | กะพริบตา                   |
| talking     | ขยับปากตามข้อความ          |
| happy       | ยิ้ม ดีใจ                  |
| annoyed     | คิ้วขมวด แก้มป่อง เท้าเอว  |
| embarrassed | หน้าแดง หลบสายตา           |
| worried     | สีหน้าเป็นห่วง             |
| surprised   | ตกใจ สะดุ้ง                |
| sleepy      | ง่วง หาว                   |
| proud       | ยิ้มภูมิใจแบบปากแข็ง       |

## Animation Technical Requirements

Idle: 4–6 Frames

Blink: 2–3 Frames

Talking: 3 Mouth Frames

Emotion Transitions: 2–4 Frames ตามความเหมาะสม

ให้ใช้ Sprite Sheet, Layered Sprites หรือระบบ Animation เดิมที่มีอยู่

ไม่ต้องสร้างระบบ Animation ใหม่หากระบบเก่ารองรับแล้ว

ระหว่าง Dialogue Typewriter Effect ให้สลับเฟรมปากตามจังหวะการแสดงข้อความ

เมื่อแสดงข้อความครบ ให้กลับสู่ Idle หรือคงสีหน้าตามอีเวนต์ช่วงสั้น ๆ

รองรับ Reduced Motion และปุ่มปิด Animation

**ยังไม่มีเสียงพูดในเวอร์ชันนี้**

ห้ามเพิ่ม Cloud TTS หรือ Voice Generation

## Dialogue Randomization

- สุ่มประโยคจากอีเวนต์ที่ตรงเงื่อนไข
- หลีกเลี่ยงประโยคซ้ำล่าสุด 3 ครั้งเมื่อมีตัวเลือกเพียงพอ
- จำกัดความถี่ของการพูด
- มี Cooldown แยกตาม Event
- อีเวนต์สำคัญต้องมี Priority สูงกว่าอีเวนต์ทั่วไป
- บทพูดเดียวกันอาจแสดงคนละสีหน้าตามบริบทได้
- บันทึกประวัติ Event ที่เคย Trigger
- การแก้ไขข้อมูลย้อนหลังต้องไม่ทำให้รางวัลหรือบทพูดสำคัญถูกยิงซ้ำโดยไม่ตั้งใจ

# PART 5 — COFFEE EVENT SYSTEM

**ระบบกาแฟเป็นอีเวนต์พิเศษของยูอิ และต้องให้ความสำคัญมากกว่าหมวดรายจ่ายทั่วไป**

ต้องรองรับ:

- จำนวนแก้วกาแฟที่ซื้อในแต่ละวัน
- กาแฟของผู้ใช้
- กาแฟที่ซื้อให้แฟน
- จำนวนแก้วรวม
- ยอดใช้จ่ายกาแฟประจำรอบ
- เปรียบเทียบงบกาแฟ
- เปรียบเทียบกับรอบก่อน

การนับจำนวนแก้วต้องใช้จำนวนสินค้าจริง ไม่ใช่จำนวนธุรกรรม

ถ้าไม่ทราบจำนวนแก้วหรือผู้รับ อย่าสมมติเอง

## C01 — กาแฟทั่วไป

กำหนดบทพูด 8 บรรทัด:

1. "กาแฟรอบนี้ใกล้แตะงบแล้วนะ... อย่าหาว่าฉันไม่เตือนล่ะ"
2. "อืม... หมวดกาแฟใช้ไปเยอะพอตัวแล้วนะ"
3. "ไม่ได้จะบ่นหรอกนะ แต่ถ้าลดแก้วนึงได้ก็ดี"
4. "กาแฟอีกแล้วเหรอ... ชอบขนาดนั้นเลยหรือไง"
5. "ฉันไม่ได้ห้ามกินสักหน่อย แค่บอกให้ดูยอดเงินด้วย"
6. "แก้วนี้หอมขนาดนั้นเลยเหรอ... ช่างเถอะ อย่าลืมบันทึกก็แล้วกัน"
7. "อืม ซื้อกาแฟเรียบร้อยแล้ว ทีนี้มาดูงบที่เหลือกันหน่อยไหม"
8. "มีความสุขกับกาแฟก็ดีอยู่หรอก... แต่เหลือเงินเก็บไว้ด้วยล่ะ"

หมายเหตุ: ประโยคเตือนใกล้แตะงบต้องใช้เฉพาะเมื่อยอดใกล้ถึงงบจริง

## C02 — กาแฟแก้วที่สองของวัน

Trigger: จำนวนแก้วที่ซื้อรวมในวันนั้นถึง 2 แก้ว

Emotion: annoyed / surprised

1. "เดี๋ยวนะ! นี่แก้วที่สองของวันนี้แล้วไม่ใช่เหรอ... ฉันนับอยู่นะ!"
2. "กาแฟอีกแก้วแล้วเหรอ... วันนี้ตั้งใจจะเปิดร้านกาแฟเองหรือไง"
3. "สองแก้วในวันเดียว... อืม ฉันควรจดไว้เป็นเหตุการณ์พิเศษไหมนะ"
4. "ไม่ได้จับผิดสักหน่อย! แค่เธอซื้อกาแฟสองแก้วแล้วต่างหาก"
5. "แก้วที่สองแล้วนะ... ดื่มน้ำเปล่าบ้างก็ดี ฉันแค่เตือนเฉย ๆ"

## C03 — กาแฟครบสามแก้ว รวมของแฟน

Trigger: จำนวนแก้วรวมถึง 3 และมีรายการซื้อให้แฟนอย่างน้อยหนึ่งแก้ว

Emotion: surprised / embarrassed / annoyed

1. "สามแก้วแล้วนะ! ...อ๋อ มีของแฟนด้วยเหรอ งั้นก็อีกเรื่องหนึ่ง แต่เงินออกไปสามแก้วอยู่ดี!"
2. "เดี๋ยวนะ สามแก้ว!? ...ซื้อให้แฟนด้วยสินะ บอกกันก่อนสิ ฉันตกใจหมด"
3. "ใจดีซื้อให้แฟนด้วยเหรอ... ก็ไม่ได้ว่าอะไรหรอก แต่ดูงบรวมด้วยนะ"
4. "วันนี้ร้านกาแฟคงจำหน้าเธอได้แล้วล่ะ... แถมยังมีของแฟนอีกด้วย"
5. "ฉันไม่ได้อิจฉาหรอกนะ! แค่สงสัยว่าทำไมวันนี้มีรายการกาแฟตั้งสามแก้ว"

## C04 — กาแฟเกินงบ

Emotion: worried / annoyed

1. "กาแฟเกินงบแล้วนะ... คราวนี้ฉันคงต้องทำหน้าเข้มสักหน่อย"
2. "เห็นยอดกาแฟแล้ว... อืม มาคิดกันว่าจะปรับงบหรือพักซื้อสักวันดีไหม"
3. "ฉันไม่ได้จะยึดแก้วกาแฟหรอกนะ แค่รอบนี้ใช้เกินที่ตั้งไว้แล้ว"
4. "กาแฟดี ๆ ก็มีความสุขได้ แต่ไม่จำเป็นต้องซื้อทุกครั้งก็ได้นี่"
5. "เกินงบกาแฟแล้วนะ... ถ้าจะซื้ออีกก็ต้องรู้ตัวเลขที่เหลือก่อนล่ะ"

## C05 — ค่ากาแฟลดลงจากรอบก่อน

Emotion: happy / embarrassed

1. "อืม รอบนี้ค่ากาแฟลดลงด้วย... ก็ทำได้ดีนี่"
2. "ฉันเห็นนะว่ารอบนี้คุมกาแฟได้ดีขึ้น ไม่เลวเลย"
3. "กาแฟยังมีความสุขเหมือนเดิม แต่จ่ายน้อยลง... เก่งเหมือนกันนี่"
4. "ดีล่ะ งบกาแฟเหลือมากกว่ารอบก่อน ฉันแค่บังเอิญสังเกตเห็นหรอก"
5. "ดูเหมือนเธอจะเริ่มหาจุดสมดุลได้แล้วนะ... ดีใจด้วยนิดหน่อยก็ได้"

## Coffee Event Priority

ถ้าซื้อกาแฟ 3 แก้วในธุรกรรมเดียว ให้ยิงอีเวนต์ระดับสูงสุดเพียงครั้งเดียว

หากมีแฟนรวมอยู่ให้เลือก C03

หากไม่มีข้อมูลแฟน ให้ใช้อีเวนต์สามแก้วแบบทั่วไปแทน ห้ามอ้างว่าผู้ใช้ดื่มเองสามแก้ว

ควรมี Event สำหรับกาแฟแก้วแรก กาแฟสามแก้วทั่วไป และกาแฟใกล้ถึงงบ 80% เพิ่มเติม

ใช้วันที่ท้องถิ่นในการนับ ไม่ใช้ UTC Day Boundary

## GROUP A — DAILY ROUTINE

### E01 — เปิดแอปตอนเช้า

- Trigger
- Condition
- Priority
- Cooldown
- Emotion
- Animation
- Dialogue 5 Lines
- Once-per-day / Once-per-period / Repeatable Setting

หาก Event ที่มีอยู่แล้วตรงกัน ให้รวมเข้ากับของเดิม ไม่สร้าง ID ซ้ำ

# PART 8 — AFFINITY & PERSONALITY EVOLUTION

ระบบความสนิทแยกจาก Rank ทางการเงิน

Affinity เพิ่มจาก:

- บันทึกรายการอย่างสม่ำเสมอ
- เปิดแอปและมีปฏิสัมพันธ์
- ทำ Achievement สำเร็จ
- ทำภารกิจประจำรอบ
- ปลดล็อกเนื้อหาตัวละคร

ไม่ควรเพิ่ม Affinity จากจำนวนเงินที่ใช้จ่ายหรือการสร้างธุรกรรมจำนวนมาก เพื่อไม่ส่งเสริมการใช้เงินเกินจำเป็นหรือการบันทึกรายการปลอม

## Affinity Tiers

### Tier 1 — ยังไม่สนิท

ยูอิพูดตรง เจ้าระเบียบ และบ่นง่าย

### Tier 2 — เริ่มคุ้นเคย

เริ่มแซวมากขึ้นและพูดเป็นกันเอง

### Tier 3 — เพื่อนสนิท

เริ่มแสดงความเป็นห่วงอย่างชัดเจน

### Tier 4 — ไว้ใจ

บทพูดอ่อนโยนขึ้น แต่ยังซึนเดเระ

### Tier 5 — คู่หูสมุดเวท

เปิดเผยความรู้สึกและภูมิใจในความก้าวหน้าของผู้ใช้มากขึ้น

แต่ละ Tier สามารถปลดล็อก:

- บทพูดใหม่
- สีหน้าใหม่
- ชุดพิเศษ
- ทรงผมพิเศษ
- ท่าทางใหม่
- ของตกแต่งห้อง
- Character Memories

ห้ามให้ความสนิทลดลงอย่างรุนแรงเพียงเพราะไม่ได้เข้าแอปหลายวัน

# PART 9 — SECOND CHARACTER SUPPORT

ให้รองรับตัวละครที่สองที่มีอยู่แล้วหรือเตรียมเพิ่มในอนาคต

แนวทางตัวละครที่สอง:

- Chibi 2D Pixel Art
- บุคลิกขี้เล่น
- กิ๊บติดผมรูปหัวกะโหลกเป็นเอกลักษณ์
- มีชุดและทรงผมของตัวเอง
- มี Dialogue Bank แยกจากยูอิ
- มี Event Reaction และ Affinity แยกกัน
- รองรับการสลับตัวละครในแอป

หากตัวละครที่สองมีอยู่ในโปรเจกต์แล้ว ให้รักษาชื่อ ภาพ และข้อมูลที่ผู้ใช้กำหนดไว้ ไม่เปลี่ยนชื่อหรือออกแบบใหม่โดยไม่ได้รับอนุญาต

ห้ามใช้บทพูดซึนเดเระของยูอิกับตัวละครทุกตัวโดยอัตโนมัติ

# PART 10 — WARDROBE & ROOM INTEGRATION

เชื่อมระบบบทพูดเข้ากับ Wardrobe และ Magical Room ที่มีอยู่แล้ว

## Wardrobe Events

เมื่อเปลี่ยนชุด:

- ยูอิอาจเขิน
- อาจแซวผู้ใช้
- อาจชมชุดใหม่แบบปากแข็ง
- เปลี่ยน Animation ตามชุด
- ไม่ต้องพูดทุกครั้งหากเปลี่ยนชุดต่อเนื่องหลายครั้ง

เมื่อปลดล็อกเครื่องประดับ:

- แสดงข้อความเฉลิมฉลอง
- แสดงสีหน้าดีใจหรือเขิน
- ห้ามสร้างรางวัลซ้ำหากเคยปลดล็อกแล้ว

## Room Events

ฉากหลัก:

- ห้องหอคอยใต้หลังคา
- ไม้สีดำและน้ำตาลเข้ม
- แสงตะเกียงสีทอง
- หน้าต่างกระจกสีสามช่อง
- เตียง
- โต๊ะหนังสือ
- นาฬิกาเวทมนตร์กลางห้อง
- คริสตัลเรืองแสง
- แมวดำ
- เครื่องประดับเวทมนตร์

ยูอิควรตอบสนองเมื่อ:

- เข้าห้อง
- ปลดล็อกของใหม่
- เปลี่ยนของตกแต่ง
- อัปเกรดห้อง
- บันทึกต่อเนื่องจนได้รับรางวัล

ไม่ต้องเปลี่ยน Room System เดิมหากใช้งานได้แล้ว

# PART 11 — RANK & PROGRESSION INTEGRATION

ตรวจสอบระบบ Rank เดิมก่อน

แนวคิดความก้าวหน้าที่เคยกำหนดไว้:

- แม่มดฝึกหัด
- แม่มดเริ่มต้น
- แม่มดชำนาญการ
- แม่มดขั้นสูง
- แม่มดอาวุโส

แนวทางสำคัญ:

- เลื่อนขั้นจากความสม่ำเสมอในการบันทึก
- จำนวนแหล่งรายได้จริง
- เงินคงเหลือ
- เงินออม
- Passive Income
- ประเมินตามรอบเงินเดือน

ตัวอย่างเงื่อนไขต้นแบบ:

แม่มดเริ่มต้น:

- มีรายได้อย่างน้อย 2 ทาง
- เงินคงเหลือปลายรอบอย่างน้อย 1,000 บาท

แม่มดชำนาญการ:

- มีรายได้อย่างน้อย 3 ทาง
- เงินคงเหลือปลายรอบอย่างน้อย 10,000 บาท

แม่มดอาวุโส:

- มีรายได้อย่างน้อย 4 ทาง
- Passive Income อย่างน้อย 1,000 บาทต่อรอบ
- มีเงินออมอย่างน้อย 1,000 บาทตามเกณฑ์ที่กำหนด

**ตัวเลขเหล่านี้เป็น Concept Reference เท่านั้น ไม่ใช่คำสั่งให้เขียนทับเกณฑ์แรงก์เดิม**

หากระบบ Rank ปัจจุบันมีเกณฑ์ที่พัฒนาและทดสอบแล้ว ให้รักษาเกณฑ์นั้นไว้และนำ Event ไปเชื่อมต่อแทน

ระบบบทพูดควรตอบสนองต่อ:

- ใกล้เลื่อนแรงก์
- ผ่านการประเมินแรงก์
- ปลดล็อกรางวัล
- ทำ Achievement
- ได้ชุดใหม่จากแรงก์
- ได้ของแต่งห้องจากแรงก์

# PART 12 — EVENT ENGINE SAFETY

ข้อกำหนดสำคัญ:

1. Event ต้องไม่แก้ไขข้อมูลทางการเงินจริง
2. ใช้การอ่านข้อมูลจากบริการบัญชีเดิม
3. ห้ามคำนวณรายรับ–รายจ่ายซ้ำแล้วนำผลไปเขียนทับระบบหลัก
4. ห้ามสร้าง Event ซ้ำทุกครั้งที่ React Component Re-render
5. ใช้ Stable Event ID
6. มี Event History และ Idempotency
7. เมื่อแก้รายการย้อนหลัง ให้ประเมินเงื่อนไขอย่างถูกต้อง
8. เมื่อสลับตัวละคร ต้องไม่ทำให้ Event History หาย
9. เมื่อเปลี่ยนชุด ต้องไม่ Reset Affinity
10. เมื่อเพิ่ม Dialogue ใหม่ ต้องไม่ Reset Achievement
11. เมื่อ Upgrade Database ต้องรักษาข้อมูลเดิมทั้งหมด
12. เมื่อไม่มี Event ให้แสดง Idle Animation แทน

ให้มี Rank UpEvent Priority เช่น:

1. Character Unlock
2. Achievement / Savings Goal
3. Salary Received
4. Debt Due Warning
5. Budget Overrun
6. Special Coffee Event
7. Transaction Success
8. General Greeting

หากมี Event หลายตัวพร้อมกัน ให้จัด Queue อย่างเหมาะสม ไม่เปิด Dialogue หลายอันซ้อนกัน

6. Event กาแฟสามแก้วรวมของแฟนทำงาน
7. นับจำนวนแก้วแยกจากจำนวนธุรกรรม
8. Event เตือนงบไม่แสดงเมื่อยังไม่ถึงเงื่อนไข
9. เลื่อนแรงก์แล้วเล่น Animation ที่ถูกต้อง
10. ปลดล็อกชุดแล้วแสดงบทพูด
11. เปลี่ยนชุดแล้วบทพูดยังทำงาน
12. เปลี่ยนตัวละครแล้วไม่ปะปน Dialogue
13. Idle และ Blink ทำงาน
14. Talking Animation ทำงานพร้อม Typewriter Effect
15. Refresh แล้วสถานะตัวละครยังอยู่
16. เปิดออฟไลน์แล้วบทพูดยังทำงาน
17. ไม่มีการเชื่อม Cloud AI
18. ไม่มีการแก้ไขยอดเงินจาก Character System
19. ระบบรายรับ–รายจ่ายเดิมยังใช้งานได้
20. ระบบ Rank และ Progression เดิมยังใช้งานได้
