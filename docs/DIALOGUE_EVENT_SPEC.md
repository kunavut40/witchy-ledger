# Dialogue and event specification

ทุกอย่างทำงานออฟไลน์ ไม่มี AI Cloud, TTS หรือเสียงพูดใหม่ ใช้คลังข้อความอ่านได้และเงื่อนไข TypeScript ไม่ประมวลผลโค้ดจากข้อความ

## Source of truth

- `src/fantasy/dialogueBank.json`: E01–E51 และ C01–C05 รวม 56 อีเวนต์ แต่ละตัวละครมีอย่างน้อยห้าบรรทัดต่ออีเวนต์ รวมบทพูดเดิมที่ใช้งานได้
- `src/fantasy/events.ts`: ID, ชื่อ, trigger, condition, priority, cooldown, scope, emotion, animation
- `src/fantasy/engine.ts`: เงื่อนไขจากข้อมูลจริง การเลือกบทพูด และประวัติ
- `src/fantasy/runtime.ts`: อ่านบัญชีและบันทึกเฉพาะ settings ผ่านคิวงานตามลำดับ

## Coffee semantics

`transaction.coffee = { cups, partnerCups }` เป็นข้อมูลไม่บังคับ จำนวนเต็มรวม 1–100 แก้ว จำนวนของแฟนเป็น 0..cups หรือ `null` เมื่อไม่ทราบ เว้นว่างทั้งชุดหมายถึงไม่ทราบจำนวน ไม่ใช่หนึ่งแก้ว

นับด้วย `transaction.date` ท้องถิ่น เฉพาะรายจ่ายหมวดกาแฟ ถ้ามีรายการที่ไม่ทราบจำนวนในวันเดียวกัน จะไม่ใช้บทพูดที่ยืนยันยอดรวมแน่นอน

- C02: รวมเท่ากับสองแก้ว
- C03: รวมเท่ากับสามแก้ว และระบุซื้อให้แฟนอย่างน้อยหนึ่ง
- E32: สามแก้วโดยไม่มีหลักฐานว่าซื้อให้แฟน ไม่อ้างว่าผู้ใช้ดื่มเองทั้งหมด
- E31: หนึ่งแก้วที่ระบุชัดเจน
- มากกว่าสามแก้วหรือข้อมูลไม่ครบ: C01 แบบทั่วไป โดยไม่ยืนยันจำนวนผิด
- กาแฟเกินงบ C04 มาก่อนจำนวนแก้ว; ใกล้งบ E33 ใช้งบกาแฟจริง ไม่ใช่งบอาหารทั้งหมด
- C05 เปรียบเทียบสองรอบที่ปิดแล้วและยาวเท่ากัน ไม่เทียบรอบปัจจุบันที่ยังไม่จบกับรอบเต็ม

เลือกเพียงอีเวนต์กาแฟที่สำคัญที่สุดต่อการบันทึกหนึ่งครั้ง

## Queue, cooldown and idempotency

ลำดับความสำคัญ: ผู้ช่วยใหม่/แรงก์ > เป้าหมายและความสำเร็จ > เงินเดือน > หนี้ใกล้ครบกำหนด > งบ > กาแฟ > ความสำเร็จการบันทึก > ทักทาย ใช้คิวเดียว ไม่เปิดหลายกล่องทับกัน จำกัดคิว 12 รายการและอายุ 10 นาที อีเวนต์สำคัญแทนบทพูดบันทึกทั่วไปในรอบประเมินเดียวกัน

คีย์ = event ID + วัน/รอบ/รายการ/เป้าหมาย/ระดับที่เกี่ยวข้อง อีเวนต์ once ใช้คีย์กลาง ส่วนการทักทายและปฏิกิริยาทั่วไปแยกตัวละคร มี cooldown รายอีเวนต์ (แต่งตัว 15 วินาที รายการทั่วไป 4 วินาที อีเวนต์อื่นอย่างน้อย 60 วินาที)

สุ่มเฉพาะบรรทัดที่ไม่อยู่ในสามบรรทัดล่าสุดเมื่อมีตัวเลือกเพียงพอ ประวัติถูกบันทึกเมื่อเข้าคิว การเปลี่ยนหน้า/ชุดไม่ล้างประวัติ การแก้รายการเดิมไม่ถือเป็นการสร้างรายการใหม่ หากแก้หรือลบรายการที่เป็นหลักฐานของข้อความในคิว จะถอนข้อความนั้น

ติดตั้งครั้งแรกเก็บ baseline รายการและความสำเร็จที่มีแล้ว ไม่เล่นรางวัลย้อนหลัง โหมดปลดล็อกทดสอบและเลือกกรอบแรงก์ไม่ถือเป็นเลื่อนแรงก์จริง

## Adding an event

1. เพิ่ม ID ที่ไม่ซ้ำใน JSON พร้อมบทพูด Yui/Momo อย่างน้อยคนละห้าบรรทัด
2. เพิ่ม metadata ใน `events.ts` และเงื่อนไขใน pure engine ให้ใช้ข้อมูลที่มีจริง
3. เลือก scope และคีย์ที่เสถียร ห้ามอาศัยเลขสุ่มหรือ render count สำหรับรางวัล
4. เพิ่มการทดสอบเงื่อนไขบวก/ลบ การรันซ้ำ และการไม่เปลี่ยนบัญชี
5. การแก้ถ้อยคำใช้ ID บรรทัดเดิมเมื่อทำได้ ไม่ล้าง runtime, affinity หรือ achievements
